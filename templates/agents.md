# Project Agent Rules

These rules apply to agents working in this project repository.

## Language And Style

- Use English for code, comments, documentation, filenames, and reports.
- Follow the existing codebase style before introducing new patterns.
- Keep changes small and reviewable.

## Security

- Do not add secrets, credentials, API keys, tokens, private keys, or customer data.
- Use placeholders for sensitive values.
- Do not connect external services unless explicitly approved.

## Git And Release Boundaries

- Do not publish, deploy, merge, push, tag releases, or modify repository settings unless explicitly instructed.
- Do not change GitHub Actions, secrets, branch protection, webhooks, or access settings without approval.

## Reporting

- Update relevant project reports after meaningful changes.
- Include commands run, validation results, errors, and follow-up recommendations.
- Escalate blockers clearly instead of expanding scope silently.

## Tooling Preference

- Prefer project-local tooling.
- Prefer standard library or existing dependencies.
- Add new dependencies only when necessary and approved.
